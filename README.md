# Statistical mechanics of spike trains

MATLAB code for Monte Carlo sampling of fixed-spike-count spike-train ensembles with refractory constraints, accompanying the manuscript **Statistical Mechanics of Spike Trains: Self-Consistent Activity Ensembles and Phase Transitions**.

The repository includes the sampler, graph and delay generation, state validation tests, numerical results, and scripts for generating phase-map figures.

## Numerical experiments

The main phase map uses **100,000 Monte Carlo iterations per grid point**. Each point represents one quenched graph-and-delay realization and one finite Markov chain. The resulting map is a single-realization finite-size phase portrait; it is not a disorder-averaged phase diagram.

Seven points failed during the original main-grid calculations. These points were subsequently computed separately and are stored in `results/raw/missing_exprnd_fix/`. They form part of the main-map reconstruction. The directory name is historical; it should not be interpreted as a definitive diagnosis of every failed calculation.

A separate, coarser grid uses **1,000,000 iterations per point**. It was added to assess whether the 100,000-iteration results had reached convergence within reasonable limits. This is a convergence check rather than the input to the main entropy figures. Longer runs alone do not establish convergence at every point or disorder averaging.

| Parameter | Main map | Longer-run check |
| --- | --- | --- |
| Neurons, `N` | 100 | 100 |
| Time bins, `T` | 500 | 500 |
| Total spikes | 500 | 500 |
| Connection probability | 0.3 | 0.3 |
| Delay mean parameter | 5 | 5 |
| Refractory duration | 3 | 3 |
| Nonlinearity | `heaviside3` | `heaviside3` |
| Beta range and step | 0:6, step 0.2 | 0:6, step 0.5 |
| Delay standard-deviation parameter and step | 0:4.5, step 0.15 | 0:4.5, step 0.9 |
| Iterations per point | 100,000 | 1,000,000 |
| Snapshot interval, `n_snap` | 10,000 | 100,000 |

The delay parameters are inputs to the sampling procedure. The finite sampled delays need not have exactly these empirical moments. The scripts are authoritative for parameter settings.

## Repository layout

- `src/`: MATLAB source functions.
- `tests/`: state, proposal, sampler, and transfer-operator tests.
- `scripts/current/`: simulation, reconstruction, plotting, and SLURM scripts.
- `results/raw/beta_0_2/`, `beta_2p2_4/`, and `beta_4p2_6/`: main-map outputs.
- `results/raw/missing_exprnd_fix/`: seven separately computed replacement points.
- `results/raw/beta_0_6_sparse_1M/`: longer-run convergence-check outputs.
- `results/raw/smoke_test/`: small example outputs.
- `results/processed/main_map/`: reconstructed main-map MAT files and synchronized TXT exports, generated by the merge script.
- `figures/phase_entropy_h3/`: processed entropy arrays and PNG/PDF figures.

## Requirements

MATLAB is required for simulations, tests, and the MATLAB figure pipeline. The included cluster scripts load MATLAB **R2025b** through a site-specific module. This identifies the configured cluster environment, not a tested minimum MATLAB version.

`src/exprnd.m` provides a local exponential sampler used by the simulation code. Add `src/` to the MATLAB path as shown below.

The optional Python analysis script requires Python with NumPy, Matplotlib, SciPy, and h5py. SLURM and the cluster module system are needed only for the supplied cluster submission scripts.

## Quick start

From the repository root in MATLAB:

```matlab
run('tests/run_all_tests.m');
run('scripts/current/run_phase_smoke_test.m');
```

The test runner invokes eight tests covering initialization, spike-count and refractory invariants, proposals, sampler behavior, and transfer-operator conventions. The smoke run uses a small system and writes results to `results/raw/smoke_test/`.

These checks do not by themselves establish equilibration or mixing of production chains.

## Recreate the main figures from supplied data

Reconstruct the main map, then generate the entropy figures:

```matlab
run('scripts/current/merge_missing_exprnd_points.m');
run('scripts/current/plot_entropy_maps_matlab.m');
```

The merge reads the three raw batches and the seven replacement files. It validates coordinates, experiment parameters, ensemble constraints, and finite results, then writes complete batches to `results/processed/main_map/`. Raw files are preserved. Repeating the merge rebuilds the outputs from raw inputs without accumulating reconstruction-history entries.

Each processed MAT file includes `source_file_grid`, `seed_grid`, and `reconstruction_history`, recording the repository-relative origin and run seed of each replacement. A run seed identifies the source calculation; it is not an independently assigned random seed for each original grid point. The matching `*_Efinal.txt` export is regenerated from the reconstructed arrays. Original raw TXT files retain the historical failures.

The plotting script reads only the reconstructed batches. For each valid point it computes normalized temporal entropy, `-sum(p .* log(p))/log(T)`, and IPR, `sum(p.^2)`, where `p = x/sum(x)` and zero entries are omitted from the logarithm. Processed figure arrays and PNG/PDF figures are written to `figures/phase_entropy_h3/`.

## Run the longer convergence-check calculations

```matlab
run('scripts/current/run_convergence_beta_0_2.m');
run('scripts/current/run_convergence_beta_2p5_4.m');
run('scripts/current/run_convergence_beta_4p5_6.m');
```

These scripts write to `results/raw/beta_0_6_sparse_1M/`. The second and third batches start at beta 2.5 and 4.5, respectively, to avoid overlapping points.

## Rerun the main calculations

The main-map beta batches are 0–2, 2.2–4, and 4.2–6:

```matlab
run('scripts/current/run_main_beta_0_2.m');
run('scripts/current/run_main_beta_2p2_4.m');
run('scripts/current/run_main_beta_4p2_6.m');
```

`run_missing_exprnd_points.m` reruns the seven historical replacement points with their individual seeds. Use `merge_missing_exprnd_points.m` to reconstruct the historical map from the original main-grid outputs and these replacements. A fresh main-grid run with the current code may complete these points without replacement; inspect its diagnostics before applying historical patches.

Simulation runs overwrite existing outputs with the same prefix. Use a separate checkout or change output prefixes to preserve the supplied reference results.

## Cluster execution

The supplied `.sbatch` files and `submit_convergence_1M.sh` are examples for the original cluster. Adapt the partition, resource limits, and `module load trytonp/matlab/R2025b` to your installation. Submit from the repository root and create `results/logs/` before submission so that SLURM can open its log files.

The three `run_main_beta_*.sbatch` wrappers invoke the matching 100k main-map scripts. For a longer-run check, use the generic wrapper with a convergence script, for example:

```bash
mkdir -p results/logs
sbatch --job-name=convergence_b0_2 scripts/current/submit_convergence_1M.sh scripts/current/run_convergence_beta_0_2.m
```

Scripts previously named `run_phase_beta_*` have been renamed to explicitly identify their experiment. Update external job commands accordingly.

## Diagnostics and reproducibility

Simulation MAT files contain parameters, the run seed, validity flags, spike-count and refractory checks, acceptance diagnostics, final energies, activity arrays, snapshots, and graph/delay information. They also contain a code-version label and execution metadata.

Seeds are set at the run level. Splitting or reordering a parameter grid changes random-number consumption and may produce different realizations at a given point. The seven historical replacement runs use separate seeds. Bitwise reproduction can also depend on the MATLAB version and numerical environment.

The stored code-version label is a descriptive string, not a Git commit identifier. Record the release tag and commit hash when reporting new calculations.

The supplied coarser 1M results support inspection of longer-run behavior at selected parameter values. A quantitative convergence claim should identify the compared observables, tolerances, and treatment of different graph/delay realizations.

For static checks without MATLAB, run `python3 tests/check_repository_static.py`. For a full validation job on the cluster, create `results/logs/` and submit `sbatch scripts/current/run_validation.sbatch`. See `README_REPRODUCIBILITY.md` for environment overrides, data provenance, validation scope, and logs. The revised pipeline passed validation on TASK on 2026-10-08 with MATLAB module R2025b.
